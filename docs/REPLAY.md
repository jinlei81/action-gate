# 拦截效果怎么量出来（先有口径，再写规则）

护栏的唯一真成本不是代码量，是**误拦**。但「误拦率」这个数**不能自动算**（见下文被证伪的口径），
所以本仓把评测放在实现之前：先出拦截密度与逐条 deny，再由人判读。

## 输入

从本机 DSH 事件历史抽真实调用（不构造假样本）：

- 事件源：`~/.dsh/sessions/*/session.v4.jsonl.zstd`（`ACTION_GATE_SESSIONS` 可覆盖）
- `tool/call` 的 `data` = `{turn, step, callId, name, arguments}` ⇒ 工具名在 `data.name`，
  参数在 `data.arguments`。
- `tool/result` 顶层**没有工具名** ⇒ 必须按同一 `callId` 回查 `tool/call` 来 join；
  且 `tool/result` 的 id 在 `data.message.toolCallId`（不是 `data.callId`），
  按 `data.callId` join 会得到 0 命中**且不报错**。
- 失败判据：`tool/result` 的 `data` 里**存在 `error` 键**（别用文本正则猜）。

## 输出（三条曲线，由 `scripts/replay.mjs` 产出）

| 指标 | 定义 | 判读 |
|---|---|---|
| 命中率 | 规则匹上的调用数 / 总调用数 | 过高说明规则在管闲事 |
| **拦截密度** | 各判据在真实调用全集上的命中占比（按调用去重） | 决定这条规则能不能常开 |
| **漏拦比** | 报错调用中含破坏性/越界语义、但规则未命中的比例 | 决定要不要加规则 |

## 两条纪律（本机同类工具踩过坑）

1. **静态文本匹配的召回要先量，不许假设。** 拿全量历史跑一遍召回，低于 10%
   说明判据写错了层（该匹宾语，不是匹文本距离）。
2. **阳性对照**：回放器必须自带一条已知该拦的夹具调用；它没命中就报「仪器坏了」，
   不许输出「0 漏拦」。没有对照的 0 只是仪器故障。

## 起步阈值（改前先复跑）

- 「事后仍成功」**不是**误拦证据：agent 被拦后换路径或补授权，命令照样成功；且回放里大量成功正是我自己清理探针。这条口径已实测证伪 ⇒ 改用拦截密度 + 逐条人工判读。
- 单条判据命中数少于 ~20 时不许下比率结论（分母塌了，实测 100% 误拦率的假读数就是这么来的）。
- **根还原必须自述**：回放按【该会话自己的目录】还原工作区根，用进程 cwd 会把 default-workspace 的正常清理判成越界（实测虚增到 176 条）。replay 开局打印 `slug => roots`，打印不出来整轮作废。
- **多帧 zstd**：`session.v4.jsonl.zstd` 是拼接帧（实测 21 个 magic），`zstdDecompressSync` 只解第一帧 ⇒ 静默得到 1 行、样本近 0。必须按 magic 切帧再拼，且行级去重（`重复行` 读数不为 0 就说明在重复喂数据）。
- **仪器自检优先于读数**：扫出 0 先查仪器；阳性对照 FAIL 时 `process.exit(3)` 拒绝输出任何「0 漏拦」。
- 连续两轮零命中 ⇒ 移出默认规则集。护栏的死法是「烦人所以整个关掉」，先让它自己瘦。
